# SEO playbook

This playbook explains what the site already does for search engines and what you need to do after launch, in order. The technical side is built in and checked automatically. What remains is setup, patience and steady content work.

## What's already built in

| Area | What the site does |
|---|---|
| Titles and descriptions | Every page has a unique title of 65 characters or fewer and a description of 70–165 characters. The site name is appended only when it fits. |
| Canonical URLs | Every page declares one absolute URL with a trailing slash, built from `url` in `src/site.config.ts`. |
| Sitemap | `sitemap-index.xml` lists every indexable page with its real "last updated" date: the review date of a calculator or guide, and the policy date for legal pages. |
| Structured data | Each page has one connected JSON-LD graph: Organization, WebSite and WebPage, plus a BreadcrumbList. Calculators add WebApplication and FAQPage, guides add Article, hubs add ItemList, and the glossary adds DefinedTermSet. |
| Share images | Each page has its own 1200×630 image in `public/og/`, generated by `npm run og`. |
| Internal links | Links go from calculators to related calculators, guides and glossary terms, from guides to calculators and terms, and between category hubs. The footer adds popular calculators and there's an HTML site map at `/sitemap/`. |
| Guides feed | An RSS feed at `/guides/rss.xml` lets readers and aggregators follow new guides. |
| Crawl hygiene | The 404 page is `noindex`. The free `*.pages.dev` copies send `X-Robots-Tag: noindex` (see `public/_headers`), so only your domain gets indexed. |
| Speed | Pages are static HTML with small per-page scripts. Lighthouse scores 100 for performance, accessibility, best practices and SEO. |

### The automated check

`npm run seo` runs `scripts/seo-check.mjs` against the build. CI runs it on every push, so a pull request that breaks SEO fails the build. It checks:

- Titles and descriptions: present, a sensible length, and not duplicated on another page.
- Canonical and Open Graph URLs match each page's address.
- Each page has exactly one non-empty H1 and no duplicate element IDs.
- Every internal link and `#anchor` works, and every image has alt text.
- Structured data parses, and every `@id` reference in it resolves.
- Breadcrumbs point at real pages, and FAQ questions are visible on the page.
- The sitemap matches the set of indexable pages exactly.

Run it after every build: `npm run build && npm run seo`.

## 1. Before launch

1. **Set your domain.** In `src/site.config.ts`, set `url` to the exact address you will use, for example `https://www.calcvera.net` (no trailing slash). Canonical URLs, the sitemap, structured data and share image links all come from this one setting. Update `email` to an inbox on the same domain.
2. **Choose one version of the address.** Use either `www.yourdomain` or the bare `yourdomain`, never both. The config uses `www` by default. On Cloudflare Pages, `www` works with any DNS provider, and the bare domain requires your DNS to be on Cloudflare.
3. **Build and check:** `npm run build && npm run seo` must report no errors.

## 2. Hosting and domain (Cloudflare Pages)

1. Deploy as described in the README, then add your domain under **Custom domains** in the Pages project.
2. **Recommended: move your DNS to Cloudflare** (free). Add the domain as a site in Cloudflare and change the nameservers at your registrar (for example, Sav) to the two Cloudflare gives you. This lets you use both `www` and the bare domain, and unlocks the settings below.
3. **Redirect the other version** with a permanent (301) redirect. In **Rules → Redirect Rules**, create a rule that sends every request for `yourdomain.net/*` to `https://www.yourdomain.net/${1}` and keeps the query string. Cloudflare offers a ready-made template for this.
4. **Turn on HTTPS everywhere:** SSL/TLS → Edge Certificates → **Always Use HTTPS**.
5. **Leave the `pages.dev` address alone.** It stays online but tells search engines not to index it. Never link to it.
6. **AI crawlers are your call.** Cloudflare can block AI bots for new domains, and this never affects Googlebot. If you want the site to appear in AI search tools such as ChatGPT search or Perplexity, allow their search crawlers in Cloudflare's AI crawler settings (**AI Crawl Control**, or **Security → Bots** on older dashboards).

## 3. Google Search Console (day 1)

1. Go to [search.google.com/search-console](https://search.google.com/search-console) and add a **Domain** property. If your DNS is on Cloudflare, Google can verify it automatically. If you use a **URL prefix** property instead, paste the HTML-tag token into `googleSiteVerification` in `site.config.ts` and redeploy.
2. Under **Sitemaps**, submit `https://www.yourdomain.net/sitemap-index.xml`.
3. Use **URL Inspection → Request indexing** for your most important pages. There is a daily limit, so start with:
   - The home page.
   - The five category hubs.
   - The eight featured calculators: credit card payoff, debt payoff, DTI, HELOC, MCA, Schedule 1-A, ACA and IRMAA.
4. After a week or two, check these reports:
   - **Pages:** why any pages aren't indexed yet. "Discovered – currently not indexed" is normal for a new site.
   - **Core Web Vitals:** should be all green.
   - **Enhancements:** breadcrumb structured data should show as valid.

> FAQ rich results are shown only for well-known government and health sites, so don't expect FAQ snippets. The FAQ markup is still valid and helps search engines understand the page.

## 4. Bing Webmaster Tools (day 1)

1. Go to [bing.com/webmasters](https://www.bing.com/webmasters) and choose **Import from Google Search Console**. It copies your verified site and sitemap in one step.
2. Bing's index also powers DuckDuckGo, Yahoo and several AI assistants, so it's worth the five minutes.
3. **IndexNow:** in Cloudflare, turn on **Caching → Configuration → Crawler Hints**. Cloudflare will then notify Bing and other IndexNow search engines when pages change, so updates get recrawled quickly.

## 5. The first 90 days

- **Be patient.** New domains usually get little search traffic for the first one to three months. Rankings for competitive terms can take six months or more.
- **Weekly, in Search Console → Performance:**
  - Find queries where a page ranks between 8 and 20. Improve that page for those queries by adding a section, an example or a FAQ that answers the query directly.
  - Find pages with many impressions but a click-through rate under about 2%. Rewrite their `metaTitle` and `metaDescription` in `src/data/tools.ts`, or the frontmatter for guides, to make the benefit clearer.
- **Keep dates honest.** Change a page's `updated` date only when its content or figures actually change. The sitemap and structured data use these dates, and search engines learn to ignore sites whose dates change without real updates.

## 6. Seasonal calendar

Search demand for these topics is highly seasonal. Update pages *before* each peak. The rule changes behind these updates are listed in the README's yearly update calendar.

| When | Peak | What to do |
|---|---|---|
| Late Sep–Oct | ACA open enrollment starts Nov 1; Medicare open enrollment runs Oct 15–Dec 7 | Load next year's ACA applicable percentages. Refresh the ACA calculator and the subsidy-cliff guide. |
| Oct–Nov | IRS inflation adjustments; CMS announces next year's Part B premium and IRMAA brackets | Update tax brackets and IRMAA tables, and publish an "IRMAA brackets for next year" update. |
| Dec–Jan | New-year debt resolutions | Refresh the debt payoff, credit card and balance transfer pages. Consider a guide on paying off debt in the new year. |
| Jan–Apr | Tax filing season | Refresh the Schedule 1-A, tips, overtime, car loan interest and senior deduction pages for the return being filed. |
| Mid-Jan | HHS poverty guidelines | Update the FPL table used for the next ACA plan year. |
| Spring–summer | Home improvement season | Refresh the HELOC, home equity and cash-out refinance pages. |

## 7. What to publish next

Each new guide should target a specific question and link to a calculator. Good next topics, drawn from the niche research:

- HELOC requirements: credit score, CLTV and DTI limits.
- What is a good DSCR? Lender tiers and how to improve the ratio.
- No tax on tips: which occupations qualify.
- How to find your qualified overtime on your W-2 or pay stubs.
- Merchant cash advance consolidation and "stacking".
- Does paying your card before the statement date help your credit score?
- Next year's IRMAA brackets, published when CMS announces them.
- Next year's ACA subsidy changes.
- Rental property expenses investors forget (vacancy, capex, management).
- Equipment financing vs leasing.

After adding pages, run `npm run build && npm run og && npm run build` so the new pages get share images, and commit `public/og/`.

## 8. Earning links safely

- **Never buy links** or join link schemes. It violates Google's spam policies and can get the site demoted.
- **Resource pages:** credit unions, nonprofit credit counselors, libraries and university financial-literacy pages often list free calculators. Email them a short note explaining which calculator helps their readers.
- **Journalist requests:** sign up for free source-request services and answer questions where a calculator or worked example genuinely helps.
- **Communities:** answer questions on Reddit or forums with a real explanation first. Link a calculator only where it directly helps, and follow each community's rules.
- **Linkable assets:** the glossary, the 2026 ACA subsidy-cliff guide and the IRMAA bracket tables are the kind of pages people cite. Keep them accurate and current.

## 9. Trust signals (E-E-A-T)

Money topics are "Your Money or Your Life" content, so Google looks hard at who is behind them.

- Add a **real author**, and ideally a **qualified reviewer** such as a CPA, enrolled agent or CFP®, in `author` and `reviewer` in `src/site.config.ts`. Their names then appear in bylines, on the About page and in the structured data automatically. **Never invent names or credentials.**
- Keep the About, Editorial policy and Contact pages accurate, and reply to messages.
- Keep sources current. The SEO check verifies structure, not facts. Re-check figures against [`DATA-SOURCES.md`](DATA-SOURCES.md) whenever agencies publish new numbers.
